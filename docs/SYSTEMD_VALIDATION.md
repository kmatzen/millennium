# Systemd validation evidence

The production units were validated on 2026-08-31 using systemd 255
(`255.4-1ubuntu8.17`) on the Linux host `anima`.

```text
systemd-analyze verify host/systemd/*.service host/systemd/*.timer
```

No project unit produced an unknown-directive, invalid-value, dependency-cycle,
or calendar error. The isolated host did report expected deployment-context
warnings for executables that are installed only on the phone, plus unrelated
warnings from units already installed on `anima`; neither is a project unit
syntax failure.

The daemon sandbox was also analyzed offline after applying the same `User=`
override generated by `make install`:

```text
systemd-analyze security --offline=yes --threshold=5 daemon-merged.service
Overall exposure level for daemon-merged.service: 4.4 OK :-)
```

The release pipeline repeats `systemd-analyze verify` on Ubuntu. Any future
change to a production unit must retain an exposure score below 5.0 and must not
introduce a project-unit verification diagnostic.
